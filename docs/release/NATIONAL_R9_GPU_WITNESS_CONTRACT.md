# NATIONAL Round Nine — physical GPU witness and release acceptance contract

**Owner E5:** browser + attestation meaning. **Owner E6:** trusted workflow and execution. **Conductor:** source promotion, signer-key enrollment and release verdict. **Status:** BLOCKED until Skybot issues a genuine independently verified host-signed witness, and Conductor enrolls its public key fingerprint.

## Security boundary: a string is not a GPU

A `WEBGL_debug_renderer_info` renderer naming `virgl` is not a hardware attestation. Even real WebGL shader pixels can be generated by software. The release decision requires **both** browser-observed WebGL1 + WebGL2 actual shader draw/readback (`[51,102,153,255]` on both) **and** a fresh, independently collected, host-signed host/guest proof. A hostile guest may invent arbitrary text and files; no guest-local self-signed certificate qualifies.

The signing private key must be held by the authenticated physical Skybot controller or equivalent independently isolated verifier; it must **never be mounted into the disposable KVM, browser, GitHub job process or repository**. The signer must independently measure physical GPU/driver/access lease and guest virtual rendering, not blindly sign arbitrary evidence submitted by the guest.

The **public** key is first independently verified out of band, then its exact UTF-8 SPKI PEM SHA-256 fingerprint is enrolled by E5/Conductor in `scripts/national-qa/trusted-gpu-keys.json`. That file intentionally starts with an **empty allowlist** and the browser test fails `GPU_RELEASE_TRUST_ROOT_NOT_ENROLLED_OR_MISMATCH` until legitimate enrollment. Supplying `NATIONAL_GPU_PUBLIC_KEY_FILE` alone never creates trust.

## Required workflow fields

Use a trusted exact-source workflow and authorize one physically inspected runner. An ephemeral challenge must be created **once per attempt** by the trusted controller, transmitted to the physical host signer securely, and matched by browser QA.

- `NATIONAL_REQUIRE_HARDWARE_GPU=1`
- `NATIONAL_CHROME_ANGLE_BACKEND=gl-egl` for Skybot Intel VirGL, which launches `--use-gl=angle --use-angle=gl-egl --ozone-platform=headless` with `EGL_PLATFORM=surfaceless`; do not use SwiftShader or bypass OpenFront's WebGL gate.
- `CHROME_BIN=/opt/skybot-gpu-runtime/chrome-headless-shell-linux64/chrome-headless-shell` **only after verifying executable existence and hash/source**.
- `NATIONAL_GPU_ATTESTATION_FILE`: path to the exact signed JSON evidence below, readable inside guest only after signed host verification.
- `NATIONAL_GPU_PUBLIC_KEY_FILE`: path to the enrolled trusted Ed25519 PEM, whose SHA-256 must match the checked-in allowlist.
- `NATIONAL_GPU_ATTESTATION_CHALLENGE`: random 32-byte lowercase hex string (64 characters).
- `NATIONAL_GPU_CANDIDATE_SHA`: exact 40-character commit SHA from the approved staging candidate; `GITHUB_RUN_ID`, `GITHUB_RUN_ATTEMPT`, `RUNNER_NAME` must identify the current run/attempt/guest runner. The witness is bound to these strings; mismatches and replay fail closed.

```json
      "backend": "virgl",
      "renderer": "ANGLE (Mesa, virgl (Mesa Intel(R) HD Graphics 4600 (HSW GT2)), OpenGL ES 3.2)",

      "webgl1ShaderPixel": [51, 102, 153, 255],
      "webgl2ShaderPixel": [51, 102, 153, 255]
    }
  },
  "signature": "BASE64_ENCODED_ED25519_DETACHED_SIGNATURE"
}
```

Sign the UTF-8 bytes of `JSON.stringify(payload)` using Ed25519; `signature` must decode to exactly 64 bytes. Proof `issuedAtMs` must be at most 120 seconds old, not more than 30 seconds in the future; `expiresAtMs` must be strictly future and no more than 120 seconds after issuance. The actual browser remeasures the renderer, WebGL1+2 contexts, draw/readPixels results. The signed report must match actual unmasked WebGL1+2 renderer and pixel values. The Intel VirGL chain additionally requires the exact verified host device 8086:0412, i915, renderD128, KVM, and independently verified VirGL transport.

An independently signed physical NVIDIA/AMD/Apple path can pass the general proof shape without claiming Intel VirGL, provided its real model/vendor/driver/render node and actual guest evidence are independently established. This is **authenticated observer evidence**, not a TPM/TEE cryptographic hardware proof; compromised host/controller and a malicious trusted workflow remain outside its assurance.
